# T-0081: проверка уведомлений о настройках

Результат: TypeScript и целевые тесты прошли. Изменения сохраняются атомарно с настройками, доставляются через существующий `control.steer` и включаются в инструкции следующего запуска. Отдельный запуск модели для уведомления не создаётся.

Проверена рабочая копия ветки `ai-taskboard/T-0081` на базе `d70f33e62c0f504f9d4039b2c92b2a9b58c13fe9`. Среда: Windows, Node.js v24.14.0, npm 11.9.0.

| Критерий | Условия и свидетельства |
| --- | --- |
| 1. UI и CLI, старое и новое значение | UI в `renderer.js` сохраняет через CLI `settings`; общий обработчик в `src/cli/main.ts` записывает журнал. `settings-notices.test.ts` вызывает настоящий CLI в отдельных временных досках: 2 → 3 → 1, модель, рассуждение, режим ревью. Проверяется текст переходов. |
| 2. Активный и неактивный менеджер | Watch вызывает доставку для обеих карт запросов, `onControl` подключает существующий transport. Тест доставки проверяет независимые позиции chat/work, отложенное получение и ошибку `No active turn.`. `codex-chat-control.test.ts` проверяет steering во время инструмента и фоновые переходы между ходами с тестовым App Server. В уведомлении отдельно указаны модель и настройка рассуждения текущего запуска, а новые параметры обозначены как сохранённые для следующего запуска. |
| 3. Наследование, повторы, окна и доски | Тесты проверяют наследуемые общие лимиты и явное переопределение, повторный save и snapshot, одновременные вызовы доставки, отдельную доску, нормализацию autoReview/reviewMode и defaults. В приложении одна подписка и один запрос каждой полосы на каноническую доску; дополнительные окна используют их. |
| 4. Лимиты и очередь | `task-launch.test.ts`: очередь ждёт свободных мест, реагирует на рост, снижение и безлимитный режим. Новый тест запуска проверяет сохранённые 3, 1 и 0 при отставшем watch со значением 2. `settings-notices.test.ts`: заняты два места, появляется третье при 2 → 3; при 3 → 1 новые запуски ждут, существующие освобождают места штатно. Ноль отображается как «без ограничений». |
| 5. Быстрые изменения, восстановление, секреты, документация | Несколько CLI save до чтения watch сохраняют все переходы. Отдельно проверен save во время незавершённой доставки. Повторное создание объекта доставки читает позиции с диска; неподтверждённое событие остаётся после ошибки. Проекция неизвестных полей исключает тестовый секрет. `docs/design.md` описывает хранение, доставку и применение. |

Всего в расширенном прогоне прошли **35 тестов**. После последней правки текста о параметрах текущего запуска повторён затронутый набор: **27 тестов**, все прошли. Остальные восемь проверяют неизменённые историю, уведомления статусов и учёт токенов. Отдельно прошла проверка чтения настроек при занятой блокировке доски из `cli.test.ts`.

Первые два запуска новых тестов выявили неполные фикстуры: отсутствовали каталоги досок, затем список listeners в имитации watch. Фикстуры исправлены; повторные прогоны прошли. Временные каталоги удаляются в `t.after`; новый интеграционный тест дополнительно проверяет отсутствие своего каталога после очистки. Предупреждения `Could not save Codex token usage.` относятся к проверяемым отказам сохранения в существующем тесте учёта токенов.

Ограничения: ручной сценарий в окнах Electron и доставка настоящей модели Codex не выполнялись. Проверка транспорта использует тестовый App Server; восстановление позиций проверено повторным созданием доставки поверх сохранённых файлов, без аварийного завершения процесса Electron. При аварии между приёмом steering провайдером и записью позиции возможна повторная доставка; атомарной транзакции между провайдером и файловой системой нет.
