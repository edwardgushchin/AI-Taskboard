# Routing and style

Adapted from upstream content-routing, placement-resolver and writing-style.

| Content | Owner |
| --- | --- |
| Required agent behavior | Existing project instruction at the narrowest applicable scope |
| Project entry and quick orientation | README.md, linking into docs/README.md |
| Learning path | Tutorial |
| Steps to achieve a task | How-to |
| Commands, settings, schemas | Reference |
| Rationale and component relationships | Explanation |

Choose by content kind before choosing a filename. Keep detailed narrative out of the always-loaded context. Do not add global provider instructions or mirror files. Reuse the nearest existing owner page; move a fact only if its new home is more appropriate, updating all callers and links. Never leave two authoritative copies.

Write active, present-tense prose, short paragraphs and task-oriented headings. One H1 per page; do not skip heading levels. Use relative forward-slash links, fenced commands with a language, and safe placeholder paths. Explain an example's assumptions. Do not include credentials, personal paths, marketing claims or incident history as current product documentation.
