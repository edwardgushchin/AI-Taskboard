v0.1.3-alpha

- Urgent cards get the next free executor slot ahead of other eligible work. If milestone dates cannot be read, the queue can still start cards that do not need those dates.
- Drafts keep their confirmation after a conversation that leaves the requirements unchanged. If a requested dependency cannot be saved immediately, the board records the request and retries it. You can send messages in the card dialogue with Enter.
- Requirements clarified by the owner update the card even during review. Each submission keeps the requirements it was based on. Reviewer questions about changing requirements stay separate from defects that require rework.
- You can ask to change a card’s review mode in ordinary language. Card badges show whether the team is waiting for you or the manager, and the expert correspondence section stays expanded when the open card refreshes.
- When local Git changes conflict with acceptance, the card shows the affected paths when known. The board can resume acceptance after the conflict is cleared.
- Each board can set a daily Codex token budget. The Limits panel shows that board’s measured use and lists available Codex resets when reported by the provider.
- The board retries confirmed Codex routing timeouts for execution and review. On Windows, stopping a Codex session also terminates its child processes.
- You can retry loading task history after an error. Board refresh no longer scans manager dialogue history, and refreshing goal history releases cached payloads for it.
- The board writes shared agent instructions and project rules to separate sections of the root AGENTS.md. New manager, executor and reviewer sessions receive the current rules.
- You can archive cancelled cards from the column menu. The About window follows the board theme.
- The Windows ARM64 installer rejects x64 hosts before changing the installation. Choose the installer for your Windows architecture.
