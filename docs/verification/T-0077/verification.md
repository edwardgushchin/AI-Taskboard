## Проверка после возврата

Исправлена гонка между проверкой блокировки старта и удалением pending. Начальное восстановление и продолжение журнала удерживают постоянный `.start-gate.sqlite` до завершения удаления; `withTaskStartLock` использует его перед открытием pending и освобождает до работы с доской. Наличие карточки проверяется под барьером, поэтому отложенный старт удалённой карточки не воссоздаёт pending. Уже захваченная блокировка выбранной карточки вызывает отказ до любых изменений, включая снятие журнала до фиксации индекса. Запрос барьера восстановлением не ждёт: это исключает взаимное ожидание с запуском, которому нужна доска.

На финальных исходниках прошли **2 теста восстановления** и **9 регрессий CLI**. Новый конкурентный тест запускает отдельный процесс, который захватывает `withTaskStartLock` и останавливается перед обращением к доске. Пока он удерживает блокировку, проверяются отказы dry-run, применения и продолжения журнала до/после фиксации индекса. В каждом случае проверена неизменность индекса, карточки, pending и журнала. Другой процесс успешно захватывает блокировку посторонней карточки, пока первый удерживает свою.

Обратный порядок проверен точными перехватами операций файловой системы: конкурентный процесс пытается захватить `withTaskStartLock` перед фиксацией журнала и при удалении карточки/pending. Он получает `BOARD_BUSY` как при первом применении, так и при продолжении журнала. Проверены варианты с pending и без него (случай T-0003), а после удаления — `TASK_NOT_FOUND` без повторного создания pending. После освобождения блокировки журнал успешно завершается. Один промежуточный запуск теста упал из-за перехвата ручной подготовки фикстуры; подготовка отделена от перехвата, финальный запуск прошёл.

## Технические детали

Первая попытка применения получила `EPERM` при создании временного файла журнала в домашней доске; данные не изменились. Через разрешённое выполнение вне песочницы запись стала доступна. Попытка передать манифест через преобразования JSON PowerShell была отклонена из-за изменённого представления дат. Node прочитал исходный JSON без преобразований; dry-run и применение успешно выполнились через публичный CLI. Защиты не отключались, исходный манифест не менялся.

Для операции передают объект `{ "manifest": <исходный манифест> }` через stdin или UTF-8 input-file. Для применения добавляют `"apply": true`. Даты нужно сохранять как исходные строки. Повторное применение исходного манифеста после удаления ожидаемо отклоняется.

```powershell
node --disable-warning=ExperimentalWarning src/cli/main.ts --project 'C:\Users\eduar' --json recover-test-data --input-file '<UTF-8 JSON с manifest>'
```
