# Доска: состояния, настройки и CLI

## Типы досок

Доска проекта использует агентов и описанный ниже процесс сдачи.
Обычная доска предназначена для личных дел: пользователь меняет статус через список в карточке и настраивает названия, цвета и признак завершения колонок.
Помощник может редактировать содержание дел; исполнители, ревью, авторежим, расписание и Git-интеграция на такой доске недоступны.
Тип задаётся при создании; обычная доска не создаёт Git-репозиторий.
Проверки операций находятся в [manual-board.ts](../../src/cli/manual-board.ts).

## Состояния

| Состояние | Смысл |
| --- | --- |
| draft | Постановка ещё не утверждена |
| ready | Задача утверждена и ждёт запуска |
| in_progress | Исполнитель работает в назначенной папке |
| blocked | Записаны препятствие и условие продолжения |
| review | Результат сдан и ждёт решения |
| done | Результат принят |
| cancelled | Работа отменена с причиной |

Управление идёт через именованные действия карточки и инструменты доски.
Произвольного переноса карточек между состояниями нет.

## Проверка

reviewMode определяет приёмку: human, reviewer или manager.
В human решение принимает пользователь. В reviewer независимый ревьюер проверяет сдачу, а менеджер ведёт одобренный результат до интеграции.
В manager проверку проводит менеджер.
Возврат содержит конкретные недостатки и сохраняет карточку и рабочую папку.
Смена режима не означает принятия результата; решения проверяются по актуальной ревизии.

## Вкладки проектов

Правый клик по вкладке проекта или её кнопке закрытия не открывает меню и не переключает проект.
Настройки активной доски доступны через шестерёнку и «Файл → Настройки доски…».
Выбор, закрытие и перетаскивание вкладок сохраняются; стрелки, Home и End переключают вкладки, Delete закрывает выбранную, Alt+↑ и Alt+↓ меняют порядок.

## Настройки

Для менеджера, исполнителя и ревьюера выбираются провайдер, модель и уровень рассуждения.
agentLimits ограничивает параллельные запуски исполнителей и ревьюеров; ноль означает отсутствие ограничения.
integrationMode задаёт merge или squash. autoMode управляет автоматической работой очереди.
archiveAfterDays задаёт срок архивации закрытых задач.
Настройки сохраняются на доске; изменение лимита не прерывает уже работающего исполнителя.

## CLI

Общий формат:

```text
ai-taskboard --project "C:/projects/example" --json COMMAND
```

| Команда | Назначение |
| --- | --- |
| list, show ID | Список и содержимое карточки |
| create, update ID | Создание и изменение постановки |
| approve ID, start ID | Утверждение и подготовка работы |
| progress ID | Промежуточный результат и следующий шаг |
| block ID, resume ID | Препятствие и продолжение |
| preview ID, submit ID | Проверка снимка и сдача |
| review ID, accept ID | Чтение сдачи и приёмка |
| request-changes ID | Возврат на доработку |
| messages ID, message ID | Переписка исполнителя с менеджером |
| cleanup-status ID, cleanup ID | Проверка и уборка рабочей копии |
| settings, doctor | Настройки и диагностика |

JSON передаётся через --stdin или --input-file. --compact сокращает ответ поддерживающих его команд.
show принимает historyLimit и beforeSequence во входном JSON для чтения истории страницами.
Изменяющие команды проверяют состояние и, где требуется, ревизию карточки.
submit требует токен проверенного preview; изменение снимка делает токен устаревшим.
Для Git-сдачи используется Conventional Commit. Для результата без Git-изменений применяется noChanges: true с проверяемым итогом.
Полный актуальный список команд находится в [парсере CLI](../../src/cli/main.ts).

## Периодические задачи проекта

Расписание запускает проходы одной карточки. Успешный проход фиксируется через progress и возвращает карточку в ready со следующим временем запуска.
Пауза расписания запрещает новый автоматический проход. Продолжение уже начатой работы сохраняет назначенную папку.
Если нужна отдельная работа, периодический исполнитель создаёт или связывает дочернюю карточку через task_spawn_child.
Устойчивый ключ связывает событие с одной дочерней задачей; повтор того же ключа не создаёт дубликат.
Дочерняя задача проходит обычное выполнение и проверку. Она не может ждать своего периодического родителя как зависимость.
Проверки создания и связывания находятся в [CLI](../../src/cli/main.ts).

Лимит менеджера не настраивается. При конфликтной приёмке общий контекст менеджера занимает слот ревьюера; подробности описаны в [архитектуре](../explanation/architecture.md#ремонт-приёмки).
